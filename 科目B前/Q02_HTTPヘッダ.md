# 穴埋め02 HTTPヘッダ（対応：02_HTTPヘッダ）

1. リクエストの1行目を（　①　）、レスポンスの1行目を（　②　）という。ヘッダの終わりは（　③　）で示す。
2. 接続先のホスト名を示すHTTPのヘッダは（　④　）で、TLSのClientHelloに平文で入る接続先のホスト名は（　⑤　）である。
3. リクエスト元のスキーム・ホスト・ポートだけを示すのは（　⑥　）ヘッダ、遷移元のパスやクエリまで含みうるのは（　⑦　）ヘッダである。後者で外部に送る範囲は（　⑧　）で制御する。
4. Cache-Control の（　⑨　）は「保存してよいが使う前に再検証」、（　⑩　）は「保存しない」を意味する。個人情報を含むページには⑩を使う。
5. 以後HTTPSでしか接続させないヘッダは（　⑪　）で、初回のHTTP接続を狙う（　⑫　）を防ぐ。サブドメインにも適用するディレクティブは（　⑬　）である。
6. X-Content-Type-Options に（　⑭　）を指定すると、ブラウザは（　⑮　）ヘッダで指定したMIMEタイプ以外として解釈しない。
7. 他サイトのフレーム内への表示を禁止するヘッダは（　⑯　）で、CSPでは（　⑰　）ディレクティブで同じことができる。いずれも（　⑱　）攻撃の対策である。
8. CSPで自オリジンのスクリプトだけを許可する値は（　⑲　）である。ただしこの場合も、攻撃者が自サイト内にファイルを（　⑳　）できると、そのファイルは読み込まれてしまう。
9. 遷移先をパラメータで受け取って（　㉑　）ヘッダに出力すると、オープンリダイレクトになる。
10. 他オリジンのスクリプトに応答の読み取りを許すヘッダは（　㉒　）である。Cookie付き要求を許す Access-Control-Allow-Credentials: true は、㉒の値（　㉓　）とは併用できない。
11. 401応答でサーバが認証方式を示すヘッダは（　㉔　）、クライアントが資格情報を送るヘッダは（　㉕　）である。Basic認証のIDとパスワードは（　㉖　）でエンコードされているだけなので、TLSで保護する。
12. 401は「（　㉗　）されていない」、403は「（　㉘　）がない」ことを示す。
13. Set-Cookieの（　㉙　）属性はHTTPSのときだけCookieを送らせ、（　㉚　）属性はスクリプトからCookieを読めなくする。ただし㉚はXSSそのものは（　㉛　）。
14. SameSite=Strict は他サイトからのリクエストにCookieを（　㉜　）。SameSite=Lax は他サイトからの（　㉝　）のGETには付けるが、POSTには付けない。SameSite=None には（　㉞　）属性が必須である。
15. Domain属性を指定すると、Cookieは（　㉟　）にも送られる。名前の先頭に（　㊱　）を付けると、Secure必須、Domain禁止、Path=/ のときだけ保存される。
16. Content-Type の charset は「（　㊲　）」、Cache-Control の max-age は「（　㊳　）」、Set-Cookie の Secure は「（　㊴　）」と呼ぶ。
