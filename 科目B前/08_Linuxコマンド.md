# Linuxコマンド あんちょこ

インシデント問題のログやコマンド履歴を読むための最低限。各項目は「何をするか」「攻撃での使われ方」「解答の型」で整理している。

## 1. プロセスとジョブ

| コマンド・書き方 | 何をするか | 攻撃・試験での着眼点 |
|---|---|---|
| `コマンド &` | バックグラウンドで実行する | ― |
| `nohup コマンド &` | ログアウト（SIGHUP）しても止まらないように実行する。出力は nohup.out | 攻撃者がSSH切断後もマルウェアを動かし続ける |
| `disown` | 実行中のジョブをシェルのジョブ一覧から外し、シェル終了時にSIGHUPを送らないようにする | ファイルを消すコマンドではない（R5春Ⅰ問2で誤解して失点） |
| `ps aux`、`ps -ef` | 実行中のプロセスを一覧表示。-ef ではPPID（親プロセスID）も出る | 親子関係で起動元を特定する（R4秋Ⅰ問2：runの親がTソフトのプロセス → 脆弱性悪用で起動された） |
| `pstree -p` | プロセスの親子関係を木の形で表示 | 同上 |
| `kill PID`、`kill -9 PID` | プロセスにシグナルを送る（-9は強制終了） | 証拠保全の前に殺すと /proc の情報が消える |

- 仕様で決まっている部分：`&`、`nohup`、`disown`（bashの組込み）、SIGHUP、`-9`（SIGKILL）。
- 任意の部分：PIDの値、実行するプログラム名。

## 2. /proc（実行中のプロセスの情報）

| パス | 中身 | 試験での着眼点 |
|---|---|---|
| `/proc/PID/environ` | そのプロセスの環境変数 | 環境変数に入れたシークレット（APIキー、トークン）を読まれる。同じ利用者か管理者権限なら読める（R5秋問3） |
| `/proc/PID/cmdline` | 起動時のコマンドライン | 引数に入れたパスワードが見える |
| `/proc/PID/exe` | 実行ファイルへのリンク | 実行後にファイルを消したり置き換えたりしても、稼働中のプロセスは元の内容で動き続ける。ここから取り出して解析できる（R5春Ⅰ問2の「稼働中のファイルと内容が異なり得る」） |

- 仕様で決まっている部分：/proc 以下の各ファイル名（Linuxカーネル）。
- 任意の部分：PID。

## 3. ダウンロードと実行

| コマンド | 何をするか | 着眼点 |
|---|---|---|
| `wget URL`、`curl -O URL` | ファイルをダウンロードして保存する | ダウンロードしたファイルはディスクに残る（R5春Ⅰ問2：受付サーバに残る） |
| `curl URL \| sh` | ダウンロードした内容を保存せずにシェルで実行する | ディスクに痕跡が残りにくい |
| `chmod +x ファイル` | 実行権限を付ける | ダウンロード → chmod +x → 実行、が侵入後の典型的な流れ |
| `base64 -d` | Base64をデコードする | 攻撃コマンドをBase64で隠して渡す |

## 4. 権限

| 書き方 | 意味 | 着眼点 |
|---|---|---|
| `-rwxr-x---` | 所有者：読み書き実行、グループ：読み実行、その他：なし | 先頭の「-」は通常ファイル、「d」はディレクトリ |
| `chmod 640 ファイル` | 数字で指定（r=4、w=2、x=1）。6=rw-、4=r--、0=--- | 設定ファイルや鍵ファイルを他人に読ませない |
| `-rwsr-xr-x`（s） | setuid：実行すると所有者（rootなど）の権限で動く | `find / -perm -4000` で一覧化。不要なsetuidは権限昇格に使われる |
| `sudo コマンド` | /etc/sudoers で許可されたコマンドを別の利用者（通常root）として実行 | 許可したコマンドのオプションで任意コマンドを実行できる場合がある（tarの --checkpoint-action など） |

- R4春Ⅰ問2の解答の型：「sudoersで、tarに指定できるオプションを制限する」。tarの実行自体を禁止すると、正規の処理（ファームウェア更新）が動かなくなる。
- 仕様で決まっている部分：r・w・x・s の記号と数値、`-perm -4000`、/etc/sudoers。
- 任意の部分：ファイル名、許可するコマンドの選び方。

## 5. 定期実行（cron）

```
# 分  時  日  月  曜日  コマンド
  0   3   *   *   *     /usr/local/bin/backup.sh
```

- 上の例は毎日3時0分に backup.sh を実行する。
- 利用者ごとの設定は `crontab -e` で編集、`crontab -l` で表示。システム全体は /etc/crontab や /etc/cron.d/ （こちらは曜日の後に実行ユーザ名の欄がある）。
- 攻撃での着眼点：cronにマルウェアの再起動を登録して永続化する。調査では各利用者のcrontabと /etc/cron* を確認する。
- 仕様で決まっている部分：5つの時刻欄の並び、`*` の意味、ファイルの場所。
- 任意の部分：時刻、スクリプトのパス。

## 6. ネットワーク

| コマンド | 何をするか | 着眼点 |
|---|---|---|
| `ss -tnp`、`netstat -anp` | 通信中・待受け中のポートと、そのプロセスを表示 | C&Cサーバへの通信や、不審な待受けを見つける |
| `ip addr` | IPアドレスの表示 | ― |
| `iptables -L` | パケットフィルタの設定を表示 | 侵入者がフィルタを書き換える |

## 7. ログとアカウントの痕跡

| 場所・コマンド | 中身 | 着眼点 |
|---|---|---|
| /var/log/auth.log（Debian系）、/var/log/secure（Red Hat系） | ログイン、sudo の記録 | SSHのパスワード総当たり、不審なsudo |
| `last`、`lastb` | ログイン成功・失敗の履歴（wtmp、btmp） | 侵入の時刻と接続元 |
| ~/.bash_history | 利用者が打ったコマンドの履歴 | 攻撃者が消す（`history -c`、ファイル削除）→ ログは別サーバに転送して保管する |
| /etc/passwd、/etc/shadow | アカウント一覧、パスワードのハッシュ | 攻撃者が新しいアカウントを追加して永続化する |
| ~/.ssh/authorized_keys | SSHで公開鍵認証を許可する公開鍵の一覧 | 攻撃者が自分の公開鍵を追記して永続化する |
| /tmp、/var/tmp、/dev/shm | 誰でも書ける一時ディレクトリ | ダウンロードしたマルウェアの置き場所。調査で必ず見る（R4秋Ⅰ問3：一時ディレクトリ内のログ） |

- アクセスログには通常、POSTのボディ（送信内容）は記録されない。OSコマンドインジェクションの攻撃文字列がPOSTのボディにあると、ログからは確認できない（R4春Ⅰ問2）。

## 8. 侵入後の典型的な流れ（コマンドの並びで読む）

1. 脆弱性を突いてコマンドを実行させる（OSコマンドインジェクション、ライブラリの脆弱性）。
2. `wget`／`curl` で追加のプログラムを /tmp などにダウンロードする。
3. `chmod +x` で実行権限を付け、`nohup … &` で実行し、`disown` でシェルから切り離す。
4. cron、authorized_keys、アカウント追加などで永続化する。
5. 環境変数（/proc/PID/environ）や設定ファイルから認証情報を盗み、横展開する。
6. ~/.bash_history やログを消して痕跡を隠す。
