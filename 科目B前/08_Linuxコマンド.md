インシデント問題のログやコマンド履歴を読むための最低限。各項目は「何をするか」「攻撃での使われ方」「解答の型」で整理している。

## 1. プロセスとジョブ

| コマンド・書き方                 | 何をするか                                                                                     | 攻撃・試験での着眼点                                          |
| ------------------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `コマンド &`                 | バックグラウンドで実行する                                                                             | ―                                                   |
| `nohup コマンド &`           | <mark style="background: #FFB8EBA6;">ログアウト（SIGHUP）しても止まらないように実行する。</mark>出力は nohup.out    | 攻撃者がSSH切断後もマルウェアを動かし続ける                             |
| `disown`                 | <mark style="background: #FFB8EBA6;">実行中のジョブをシェルのジョブ一覧から外し、シェル終了時にSIGHUPを送らないようにする</mark> | ファイルを消すコマンドではない                                     |
| `ps aux`、`ps -ef`        | 実行中のプロセスを一覧表示。-ef ではPPID（親プロセスID）も出る                                                      | 親子関係で起動元を特定する（R4秋Ⅰ問2：runの親がTソフトのプロセス → 脆弱性悪用で起動された） |
| `pstree -p`              | プロセスの親子関係を木の形で表示                                                                          | 同上                                                  |
| `kill PID`、`kill -9 PID` | プロセスにシグナルを送る（-9は強制終了）                                                                     | 証拠保全の前に殺すと /proc の情報が消える                            |

- 仕様で決まっている部分：`&`、`nohup`、`disown`（bashの組込み）、SIGHUP、`-9`（SIGKILL）。

## 2. /proc（実行中のプロセスの情報）
| パス                  | 中身          | 形式        | 読める人（既定）    | 試験での着眼点                                                                                                                                                                                             |
| ------------------- | ----------- | --------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/proc/PID/environ` | そのプロセスの環境変数 | NUL区切り    | 同じ利用者か root | <mark style="background: #FFB8EBA6;">環境変数に入れたシークレット（APIキー、トークン）を読まれる。同じ利用者か管理者権限なら読める（R5秋問3）</mark>                                                                                                 |
| `/proc/PID/cmdline` | 起動時のコマンドライン | NUL区切り    | 全利用者        | 引数に入れたパスワードが見える                                                                                                                                                                                     |
| `/proc/PID/exe`     | 実行ファイルへのリンク | シンボリックリンク | 同じ利用者か root | 実行後にファイルを消したり置き換えたりしても、稼働中のプロセスは元の内容で動き続ける。ここから取り出して解析できる（R5春Ⅰ問2の「稼働中のファイルと内容が異なり得る」）。<mark style="background: #FFB8EBA6;">ディスク上のファイルが削除されたり置き換えられたりしても、稼働中のマルウェア本体をここからコピーしてハッシュ値の計算や解析ができる</mark> |
- `/proc/PID/environ` と `/proc/PID/cmdline` は、改行ではなく NUL 文字（`\0`）で区切られている。そのまま `cat` で表示すると一行につながるので、`tr '\0' '\n'` で改行に置き換えて表示する。
- `tr` ：「translate」の略で、入力された文字を、指定した別の文字に1文字ずつ置き換えて出力するコマンド
```bash
# docker(root)のコマンド
# 1. 動いているプロセスと番号を一覧で見る
ps -ef                     # 2列目がPID
pgrep -a apache2           # 名前で絞り込む場合（apache2 は例）

# 2. 見つけた番号を入れて実行する（例：PIDが1の場合）
tr '\0' '\n' < /proc/1/environ
tr '\0' ' ' < /proc/1/cmdline; echo

# 番号を調べずに試すなら、いま使っているシェル自身を見る
tr '\0' '\n' < /proc/$$/environ
tr '\0' ' ' < /proc/$$/cmdline; echo
```
- `/proc/PID/exe` は、ファイルの中身ではなく実行ファイルへのシンボリックリンクになっている。元のファイルが削除されていても `ls -l` で見ると末尾に `(deleted)` と出るだけでリンクは残っており、`cp /proc/PID/exe 保存先` で中身を取り出して `sha256sum` でハッシュ値を記録できる。
```bash
# docker(root)のコマンド
# 1. 動いているプロセスと番号を一覧で見る
ps -ef                     # 2列目がPID
pgrep -a apache2           # 名前で絞り込む場合（apache2 は例）

# 2. 見つけた番号を入れて実行する（例：PIDが1の場合）
ls -l /proc/1/exe                  # リンク先を確認（削除済みなら末尾に (deleted)）
cp /proc/1/exe /tmp/pid1.bin       # 中身を取り出す
sha256sum /tmp/pid1.bin            # ハッシュ値を表示する

# 番号を調べずに試すなら、いま使っているシェル自身を見る
ls -l /proc/$$/exe                 # → /usr/bin/bash などが表示される
cp /proc/$$/exe /tmp/shell.bin
sha256sum /tmp/shell.bin /proc/$$/exe   # 2つの値が一致する
```
- 仕様で決まっている部分：/proc 以下の各ファイル名（Linuxカーネル）。

## 3. ダウンロードと実行

| コマンド                     | 何をするか                                                                | 着眼点                                                                               |
| ------------------------ | -------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `wget URL`、`curl -O URL` | ファイルをダウンロードして保存する                                                    | <mark style="background: #FFB8EBA6;">ダウンロードしたファイルはディスクに残る（R5春Ⅰ問2：受付サーバに残る）</mark> |
| `curl URL \| sh`         | <mark style="background: #FFB8EBA6;">ダウンロードした内容を保存せずにシェルで実行する</mark> | ディスクに痕跡が残りにくい                                                                     |
| `chmod +x ファイル`          | 実行権限を付ける                                                             | <mark style="background: #FFB8EBA6;">ダウンロード → chmod +x → 実行、が侵入後の典型的な流れ</mark>    |
| `base64 -d`              | Base64をデコードする                                                        | 攻撃コマンドをBase64で隠して渡す                                                               |

## 4. 権限

権限

| 書き方              | 意味                                                                                     | 着眼点                                                               |
| ---------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `-rwxr-x---`     | <mark style="background: #FFB8EBA6;">所有者：読み書き実行（rwx）、グループ：読み実行（r-x）、その他：なし（---）</mark> | 先頭の「-」は通常ファイル、「d」はディレクトリ                                          |
| `chmod 640 ファイル` | 数字で指定（r=4、w=2、x=1）。6=rw-、4=r--、0=---                                                   | <mark style="background: #FFB8EBA6;">設定ファイルや鍵ファイルを他人に読ませない</mark> |
| `-rwsr-xr-x`     | <mark style="background: #FFB8EBA6;">setuid：実行すると所有者（rootなど）の権限で動く</mark>（rwsのs）       | `find / -perm -4000` で一覧化。不要なsetuidは権限昇格に使われる                     |
| `sudo コマンド`      | /etc/sudoers で許可されたコマンドを別の利用者（通常root）として実行                                             | 許可したコマンドのオプションで任意コマンドを実行できる場合がある（tarの --checkpoint-action など）     |

特別な権限ビット

| 位置      | 記号  | 名前                                                    | 意味                                                                               | 数字   |
| ------- | --- | ----------------------------------------------------- | -------------------------------------------------------------------------------- | ---- |
| 所有者の x  | s   | setuid                                                | 実行すると所有者の権限で動く                                                                   | 4000 |
| グループの x | s   | setgid                                                | 実行するとグループの権限で動く                                                                  | 2000 |
| その他の x  | t   | <mark style="background: #FFB8EBA6;">スティッキービット</mark> | <mark style="background: #FFB8EBA6;">ディレクトリ内のファイルを、所有者以外は削除できない（/tmp で使う）</mark> | 1000 |

- R4春Ⅰ問2の解答の型：<mark style="background: #FFB8EBA6;">「sudoersで、tarに指定できるオプションを制限する」。tarの実行自体を禁止すると、正規の処理（ファームウェア更新）が動かなくなる。</mark>
- <mark style="background: #FFB8EBA6;">sudoers では、コマンドの後ろに引数まで書くと、その引数の組み合わせでしか実行できなくなる。</mark>
- sudoersの設定例
	- -x：展開する（extract）。まとめる場合は -c（create）
	- -z：gzip で圧縮・解凍する（拡張子 .tar.gz、.tgz）
	- -f ファイル名：対象のアーカイブファイルを指定する（file）。-f の直後にファイル名を書く
	- -C ディレクトリ：指定したディレクトリに移動してから展開する。省略すると現在のディレクトリに展開される
```
# 修正前：tar にどんなオプションでも付けて root で実行できる
www ALL=NOPASSWD: /bin/tar

# 修正後：ファームウェア展開に使う引数の組み合わせだけを許可する
www ALL=NOPASSWD: /bin/tar -xzf /var/firmware/update.tar.gz -C /opt/firmware
```
- ワイルドカードには注意が必要。たとえば `/bin/tar -xzf *` と書くと、`*` は空白も含めて何にでも一致するので、後ろに `--checkpoint-action` を付け足せてしまう。
- 実務では、tar を固定の引数で呼ぶ小さなスクリプトを root 所有で作り、sudoers ではそのスクリプトだけを許可する方法もよく使われる。
- 仕様で決まっている部分：r・w・x・s の記号と数値、`-perm -4000`、/etc/sudoers。

## 5. 定期実行（cron）

```
# 分  時  日  月  曜日  コマンド
  0   3   *   *   *     /usr/local/bin/backup.sh
```

- `cron`：<mark style="background: #FFB8EBA6;">crontab に書いた「分・時・日・月・曜日」の指定に従って、コマンドを決まった時刻に自動で繰り返し実行する仕組み</mark>
- 上の例は毎日3時0分に backup.sh を実行する。
- 利用者ごとの設定は `crontab -e` で編集、`crontab -l` で表示。システム全体は /etc/crontab や /etc/cron.d/ （こちらは曜日の後に実行ユーザ名の欄がある）。
- <mark style="background: #FFB8EBA6;">攻撃での着眼点：cronにマルウェアの再起動を登録して永続化する。</mark>調査では各利用者のcrontabと /etc/cron* を確認する。
- 仕様で決まっている部分：5つの時刻欄の並び、`*` の意味、ファイルの場所。

## 7. ログとアカウントの痕跡

| 場所・コマンド                                              | 中身                      | 着眼点                                                                                         |
| ---------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------- |
| /var/log/auth.log（Debian系）、/var/log/secure（Red Hat系） | ログイン、sudo の記録           | <mark style="background: #FFB8EBA6;">SSHのパスワード総当たり、不審なsudo</mark>                           |
| `last`、`lastb`                                       | ログイン成功・失敗の履歴（wtmp、btmp） | <mark style="background: #FFB8EBA6;">侵入の時刻と接続元</mark>                                       |
| ~/.bash_history                                      | 利用者が打ったコマンドの履歴          | <mark style="background: #FFB8EBA6;">攻撃者が消す（`history -c`、ファイル削除）→ ログは別サーバに転送して保管する</mark>   |
| /etc/passwd、/etc/shadow                              | アカウント一覧、パスワードのハッシュ      | <mark style="background: #FFB8EBA6;">攻撃者が新しいアカウントを追加して永続化する</mark>                          |
| ~/.ssh/authorized_keys                               | SSHで公開鍵認証を許可する公開鍵の一覧    | <mark style="background: #FFB8EBA6;">攻撃者が自分の公開鍵を追記して永続化する</mark>                            |
| /tmp、/var/tmp、/dev/shm                               | 誰でも書ける一時ディレクトリ          | <mark style="background: #FFB8EBA6;">ダウンロードしたマルウェアの置き場所。調査で必ず見る（R4秋Ⅰ問3：一時ディレクトリ内のログ）</mark> |

- <mark style="background: #FFB8EBA6;">アクセスログには通常、POSTのボディ（送信内容）は記録されない。OSコマンドインジェクションの攻撃文字列がPOSTのボディにあると、ログからは確認できない（R4春Ⅰ問2）。</mark>

## 8. <mark style="background: #FFB8EBA6;">侵入後の典型的な流れ</mark>（コマンドの並びで読む）

1. 脆弱性を突いてコマンドを実行させる（<mark style="background: #FFB8EBA6;">OSコマンドインジェクション、ライブラリの脆弱性</mark>）。
2. `wget`／`curl` で追加のプログラムを /tmp などにダウンロードする。
3. `chmod +x` で実行権限を付け、`nohup … &` で実行し、`disown` でシェルから切り離す。
4. cron、authorized_keys、アカウント追加などで永続化する。
5. 環境変数（/proc/PID/environ）や設定ファイルから認証情報を盗み、横展開する。
6. ~/.bash_history やログを消して痕跡を隠す。
