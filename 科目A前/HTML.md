### 1. 基本構造

- 要素と属性
  - 文法：`<タグ名 属性名="値">内容</タグ名>` の形で書く。ブラウザは `<` `>` `"` などの記号を区切りとして構造を解釈する。
  - 攻撃・リスク：出力した入力値に `<` や `"` が含まれると、ブラウザがそれを区切りとして解釈し、タグや属性を追加されてしまう。これがXSSの根本原因である。
  - 対策：出力時に特殊文字を文字参照に変換する（エスケープ）。
- 文字参照
  - 文法：`&lt;`（`<`）、`&gt;`（`>`）、`&quot;`（`"`）、`&#39;`（`'`）、`&amp;`（`&`）と書いた文字は、区切りではなく「ただの文字」として表示される。
  - 対策：上記のエスケープは、この仕組みを利用している。

### 2. XSS関連

- 出力先の種類
  - 文法：入力値は本来「ただのデータ」として出力されるが、出力先ごとに決まった区切り文字が含まれると、データの範囲を抜け出し、タグや属性、コードとして解釈される。その区切り文字は出力先によって異なる。
    1. 要素の内容（例：`<p>入力値</p>`）：`<` で新しいタグを始められる。
    2. 属性値（例：`<input value="入力値">`）：`"` で属性値を閉じられる。
    3. script要素内（例：`<script>var s = '入力値';</script>`）：`'` でJavaScriptの文字列を閉じられる。また、`</script>` で要素そのものを閉じられる。
       例：攻撃文字列 `';alert(1);//` を送り込んだ場合、script要素の中身は `var s = '';alert(1);//';` になる。各部分の役割は次のとおり。
       ・`'`：文字列を閉じる（ここで抜け出す）。  
       ・`;`：`var s = ''` の文を終わらせる。  
       ・`alert(1)`：新しい文として実行される。  
       ・`;`：その文を終わらせる。  
       ・`//`：行末までをコメントにして、元のコードに残る Webアプリ側があらかじめ用意している文字列の終端と文の終端である`';` を無効にし、構文エラーを防ぐ。
    4. URLを取る属性（例：`<a href="入力値">`）：区切り文字は不要で、入力値そのものが `javascript:` で始まれば実行される。
       例
       ```
       <!-- Webアプリ側のひな形 -->
       <a href="入力値">この人のWebサイト</a>
       
       <!-- 正常な入力 https://example.com のときの出力 -->
       <a href="https://example.com">この人のWebサイト</a>
       
       <!-- 攻撃者が javascript:alert(1) を登録したときの出力 -->
       <a href="javascript:alert(1)">この人のWebサイト</a>
       ```
  - 攻撃・リスク：`<` `>` だけをエスケープしても、出力先によってはすり抜けられる。
    - 属性値に `" onmouseover="alert(1)` を入れると、`<` `>` を使わずにイベントハンドラ属性を追加できる。
      - 属性値が `"`（ダブルクォート）で囲まれていて、出力時に `"` がエスケープされていない。  
      - `'`（シングルクォート）で囲まれている場合は、`"` の代わりに `'` を使う。引用符なしの場合は、空白だけで区切れる。  
      - `"` が `&quot;` にエスケープされていれば、属性値を閉じられず失敗する。
        例
        ```
        <!-- Webアプリ側のひな形 -->
        <input type="text" name="q" value="入力値">
        
        <!-- 入力値に " onmouseover="alert(1) を入れたときの出力 -->
        <input type="text" name="q" value="" onmouseover="alert(1)">
        ```
    - script要素内に `';alert(1);//` を入れると、文字列を閉じて任意のコードを実行できる。script要素内では文字参照が解釈されないため、HTML用のエスケープは効かない。
    - href属性の値に出力される入力値として `javascript:alert(1)` を入れると、エスケープの対象になる記号（`<` `>` `"` `'` `&`）を使わずにスクリプトを実行できる。そのため、エスケープでは防げない。
  - 対策：出力先ごとに処理を変える。
    1. 要素の内容：`<` `>` `&` をエスケープする。
    2. 属性値：引用符で囲み、`"` `'` もエスケープする。
    3. script要素内：入力値を直接出力しない（必要ならJavaScript用のエスケープを行う）。
    4. URLを取る属性：`http://` または `https://` で始まるかを検査する。
- 属性値の引用符
  - 文法：属性値は、空白などを含まなければ引用符なしでも書ける。
  - 攻撃・リスク：引用符なしの属性値は空白で区切られ、その続きが別の属性として解釈される。例えば、値に「`x onmouseover=alert(1)`」を入れられると、イベントハンドラ属性が追加される。
  - 対策：属性値は必ず引用符で囲み、その引用符もエスケープする。
- イベントハンドラ属性
  - 文法：`onerror`、`onclick`、`onload` などの属性値は、JavaScriptとして実行される。`onerror` は画像の読込み失敗時に動く。
  - 攻撃・リスク：`<img src=1 onerror=alert(1)>` を注入されると、`src=1` は読み込めないため必ず `onerror` が動き、スクリプトが実行される。XSS診断の定番である。
- javascriptスキーム
  - 文法：`href` などに `javascript:…` と書くと、URLの代わりにスクリプトが実行される。

|要素と属性|用途|javascript: の実行|
|---|---|---|
|`a`・`area` の `href`|リンク先|クリック時に実行|
|`iframe` の `src`|埋め込むページ|読込み時に実行|
|`form` の `action`、`button`・`input` の `formaction`|フォームの送信先|送信時に実行|
|`img`・`video`・`audio`・`source` の `src`|画像・動画・音声|実行されない|
|`script` の `src`|外部スクリプト|実行されないが、攻撃者のURLを指定されれば任意のスクリプトが読み込まれる|
|`link` の `href`、`base` の `href`|スタイルシートなど、相対URLの基準|実行されないが、読込み先や基準URLを差し替えられる|

  - 攻撃・リスク：リンク先URLを入力値から作る処理で悪用される。記号を含まないため、エスケープでは防げない。
  - 対策：`http://` または `https://` で始まるURLだけを許可する。
- DOMベースXSS
  - 文法：JavaScriptの `innerHTML` は、代入した文字列をHTMLとして解釈する。`textContent` は、ただの文字列として扱う。
  - 攻撃・リスク：URLの一部（`location.hash` など）を `innerHTML` に渡すと、スクリプトを注入される。ブラウザ内で完結する場合は、サーバ側のログに残らないこともある。
  - 対策：`textContent` を使う。

### 3. `<head>`内

- meta charset
  - 文法：ページの文字コードを宣言する。
  - 攻撃・リスク：未指定や不一致だと、ブラウザが別の文字コードと推測し、エスケープをすり抜ける文字列が成立することがある（UTF-7を使ったXSSが古典的な例）。
  - 対策：文字コードを明示する（HTTPの `Content-Type` ヘッダでも指定する）。
- meta robots
  - 文法：検索エンジンのクローラへの指示。`noindex`（索引に載せない）、`nofollow`（リンクをたどらない）、`none`（両方）、`noarchive`（キャッシュを残さない）。
  - 攻撃・リスク：管理画面などが検索で見つかり、攻撃対象にされる（R4春午後Ⅰ問2）。
  - 対策：`noindex` を指定する。ただし、従うかどうかはクローラ次第で、アクセス制御の代わりにはならない。
- `meta http-equiv="Content-Security-Policy"`
  - 文法：HTTPヘッダと同じCSPをHTML内で指定する。ただし `frame-ancestors`、`report-uri`、`sandbox` はmeta要素では無効である。
  - 対策：XSS時の不正スクリプトの実行や読込みを制限する。
- `meta name="referrer"`
  - 文法：リンク遷移時のRefererヘッダに含める情報の範囲を指定する。
  - 攻撃・リスク：URLにセッションIDやトークンが含まれると、遷移先のサイトに漏れる。
  - 対策：`no-referrer` や `strict-origin-when-cross-origin` を指定する。

### 4. フォーム

- form要素のmethod属性
  - 文法：GETは入力値をクエリ文字列（URL）に、POSTはボディに載せて送る。
  - 攻撃・リスク：GETで送った値は、アクセスログ、ブラウザの履歴、Refererに残る。逆に調査する側からは、POSTの中身はアクセスログで見えない（R4春午後Ⅰ問2設問3(1)の論点）。
  - 対策：秘密情報はPOSTで送る。
- `input type="hidden"`
  - 文法：画面に表示しない値を、フォームと一緒に送る。
  - 攻撃・リスク：隠れているだけで、利用者は自由に書き換えられる。
  - 対策：CSRFトークンの埋め込みに使い、サーバ側でセッションとひも付けて検証する（R4春午後Ⅱ問1）。価格や権限など、信頼すべき値は置かない。
- `input type="password"`、autocomplete属性
  - 文法：入力値を伏せ字で表示する。ブラウザに入力値を保存させるかどうかのヒントを与える。
  - 攻撃・リスク：`autocomplete="off"` は無視するブラウザもあり、確実な制御にはならない。

### 5. 埋込み・外部読込み

- iframe要素
  - 文法：別のページを埋め込んで表示する。
  - 攻撃・リスク：標的サイトを透明にして罠サイトに重ねる、クリックジャッキングに使われる。
  - 対策：埋め込まれる側が、`X-Frame-Options` か CSPの `frame-ancestors` で埋込みを拒否する。iframeの `sandbox` 属性は、埋め込む側が中のページの動作を制限するもので、クリックジャッキング対策ではない。
- script要素の src属性と integrity属性
  - 文法：`src` で外部のスクリプトを読み込む。`integrity` にハッシュ値を書くと、内容が一致しない場合にブラウザが実行しない（SRI）。
  - 攻撃・リスク：CDNや外部ライブラリが改ざんされると、利用しているサイト全体に影響する（サプライチェーン攻撃）。
  - 対策：SRIを使う。
- a要素の `target="_blank"` と `rel="noopener"`
  - 文法：`target="_blank"` はリンクを新しいタブで開く。`rel="noopener"` は、開いた先のページから元のページを操作できなくする。
  - 攻撃・リスク：開いた先の悪意あるページが、元のタブを偽ページに差し替える（タブナビング）。
  - 対策：`rel="noopener"` を付ける（現行の主要ブラウザは、既定でこの動作）。

### 6. HTMLと対で出るHTTPヘッダ（HTMLの文法ではない）

- `Content-Security-Policy`：読み込めるスクリプトなどの出どころを制限する。XSS対策、クリックジャッキング対策（`frame-ancestors`）。
- `X-Frame-Options`：フレーム内での表示を禁止・制限する。クリックジャッキング対策。
- `X-Content-Type-Options: nosniff`：Content-Typeと異なる形式での解釈をブラウザに禁止する。
- Set-Cookieの属性：`Secure`（HTTPSのときだけ送る）、`HttpOnly`（JavaScriptから読めなくする。XSSで盗まれにくくなる）、`SameSite`（クロスサイトのリクエストで送らない。CSRFの軽減）。
